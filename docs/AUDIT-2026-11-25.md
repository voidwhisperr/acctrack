## 2. Що перевірено

- **128/128** автоматичних перевірок (`tests/local_test.py`): API, P&L, Eldorado, склад, аналітика, бекапи, безпека, CSV, CSRF, path traversal.

- **170 inline-обробників** кнопок — усі посилаються на наявні функції (скрипт перевірки).
- **Валюта**: UA ₴ / EN $ / RU ₽; перерахунок за курсом відповідної валюти.
- **Вхід**: без пароля → «Sign in · Ledger»; з паролем → застосунок; Ledger+ проксі → одразу застосунок.
- **Desktop**: `Ledger.exe` v1.49.0 віддає `/api/health` на 8766; `LedgerPlus.exe` відкриває живий сервер без форми входу.
- **Розгортання**: v1.49.0 на VPS, health OK, бекап у `/root/gt_versions/20261125-152314`, автовідкат готовий.

## 3. Що не вдалося перевірити повністю

- FunPay/ZeusX: cookie користувача прострочені — реальні баланси не тягнулися.
- Taobao: капча/QR-вхід — агент не проходив у реальному часі.
- Gmail IMAP і Telegram-бот: потребують живих токенів.
- Windows-сповіщення: модуль працює, але реальний лист не надсилали.
- Оплата/підписка Ledger+: у коді немає білінгу — це наступний етап.

## 4. Пропозиції після фіксів

### Візуальні
1. Онбординг на 3 кроки: мова → валюта → перший запис, з лого і прогресом.
2. Порожні стани з ілюстрацією та CTA замість «Немає даних».
3. Єдині підписи валют: у полях введення показувати `$ / ₴ / ₽` за мовою, а не завжди `$`.
4. Ліве бокове меню на широких екранах (зараз верхні таби губляться).
5. Окремий landing для Ledger+: скріншоти, тарифи, кнопка «Купити», сторінка входу.
6. Маркетинговий пак: 6–8 скріншотів, 1 GIF, обкладинка репозиторію.

### Технічні
1. SQLite замість JSON для конкурентних записів і швидких звітів.
2. WebSocket/SSE для живого оновлення між браузером і додатком.
3. Єдині JSON-словники i18n + CI-перевірка на пропущені ключі.
4. Playwright-тести 3 мов і ключових кнопок у CI.
5. Підпис exe (EV/OV сертифікат) — прибрати SmartScreen.
6. Автооновлення desktop-додатків.
7. Ролі/кілька користувачів для Ledger+ і журнал доступу.
8. Резервне копіювання на сервері за розкладом + перевірка відновлення.

### Що було зламано

| Діагностика показувала ✅ біля токена лише тому, що він **збережений** | Реальний стан: активний / прострочений / не задано / помилка | Новий `GET /api/tokens/check`: FunPay, ZeusX (реальні запити), Gmail (IMAP-логін), Telegram (`getMe`); кнопка «Перевірити токени» |

### Чому 404 не зловили в першому проході

Чесно: перша перевірка охоплювала API-тести, рендер 10 екранів і статичний пошук мертвих `onclick`-обробників. Кнопка «Скріншоти» — це `<a target="_blank">`, а не `onclick`; її ніхто не відкривав, а тека `docs` не входила в exe. Тому 404 і виник. Тепер:
- маршрут `/demo` перевіряється і в exe, і в сервері;
- окремо перевірено кількість битих зображень (0/9);
- для відсутньої демо-сторінки є безпечний fallback.

### Реальні результати перевірки токенів на хостингу

```json
{"funpay":"valid","zeusx":"valid","gmail":"valid","telegram":"valid"}
```

На desktop без збережених токенів той самий екран показує «не задано» — без фальшивих зелених галочок.
